SCHOFESTREAM 0.1.2 — JELLYFIN / CADDY CORS FIX
================================================

IMPORTANT
---------
Jellyfin is already returning:
  Access-Control-Allow-Origin: *

Do NOT add a second Access-Control-Allow-Origin header in Caddy.
Doing that produces a response like:
  Access-Control-Allow-Origin: https://schofestream.co.uk, *

Browsers reject that response because Access-Control-Allow-Origin may only have
one applicable value.

On the Jellyfin server edit:
  /etc/caddy/Caddyfile

For player.schofestream.co.uk use the simple Jellyfin reverse proxy block:

player.schofestream.co.uk {
    reverse_proxy 127.0.0.1:8096
}

Remove the custom Schofestream CORS header/preflight rules that were supplied in
Schofestream 0.1.1.

Then validate and reload:

sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy

VERIFY
------
Run:

curl -sS -D - -o /dev/null \
  -H 'Origin: https://schofestream.co.uk' \
  https://player.schofestream.co.uk/System/Info/Public \
  | grep -i '^Access-Control-Allow-Origin:'

Expected: ONE Access-Control-Allow-Origin line only. On the current Jellyfin
setup it should normally be:

Access-Control-Allow-Origin: *

Then hard-refresh Schofestream and retry playback.

If a 404 remains after CORS is fixed, inspect the Request URL for that specific
404. Do not share the api_key/ApiKey query value; only share the URL path.
